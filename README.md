# 키워드 현황

모아모아와 오늘의베스트를 하루 한 번 확인해 커뮤니티별 대표 글을 기록하고, `뜨는 주제`와 `주요 주제`를 분류하는 프로젝트입니다.

## 운영 방식

- 확인 시각: 매일 11:00 (Asia/Seoul)
- 모아모아와 오늘의베스트의 커뮤니티 합집합을 확인
- 중복 커뮤니티는 두 사이트의 결과를 교차 검증해 하나로 통합
- 커뮤니티별 지정 조합을 정확히 한 번 확인
- 각 커뮤니티에서 1위 게시물 하나만 기록
- 최근 6시간 후보는 `뜨는 주제`
- 서로 다른 커뮤니티 2곳 이상에서 반복되면 `주요 주제`

현재 관리 대상은 총 20개 커뮤니티입니다. 모아모아 10개와 오늘의베스트 18개를 합치고, 양쪽에 중복된 커뮤니티는 하나로 관리합니다.

세부 조합과 기준은 [`config/rules.json`](config/rules.json)에 있습니다.

## 사용법

1. `data/daily.example.json`을 복사해 `data/YYYY-MM-DD.json`을 만듭니다.
2. 각 커뮤니티에서 확인한 1위 글을 입력합니다.
3. 보고서를 생성합니다.

```bash
npm run report -- data/2026-08-29.json
```

결과는 `reports/YYYY-MM-DD.md`와 `reports/YYYY-MM-DD.html`에 저장됩니다.
HTML 보고서에는 뜨는 주제, 주요 주제, 원문 URL, 이번 주 영상 소재 후보와 커뮤니티별 대표 글이 대시보드 형태로 표시됩니다.
날짜별 보고서는 계속 보존되며 `reports/index.html`에 최신 날짜순으로 누적됩니다. 가장 최근 보고서가 항상 최상단에 표시됩니다.

입력 검증만 하려면 다음 명령을 사용합니다.

```bash
npm run check -- data/2026-08-29.json
```

## 데이터 원칙

- 제목 전체가 아니라 `topic`에 대표 키워드를 통일해 입력합니다.
- 같은 주제의 커뮤니티가 2곳 이상이면 주요 주제로 통합합니다.
- 단일 커뮤니티에서 최근 6시간 이내에 등장한 주제는 뜨는 주제로 분류합니다.
- 확인되지 않은 의혹은 `needsVerification: true`로 표시합니다.
- 화면에는 커뮤니티별 대표 1개만 보여주지만 내부 학습용 데이터는 커뮤니티별 상위 10개까지 저장할 수 있습니다.
- `topic`이 없으면 제목을 정규화하고 유사 토큰 비율로 자동 군집화합니다.
- 같은 커뮤니티의 여러 항목은 허용하며 `rank`가 가장 높은 항목만 대표 글로 표시합니다.
- 값이 0인 경우와 수집하지 못한 경우를 구분하기 위해 미수집 필드는 생략하고 데이터 완성도를 별도로 표시합니다.

## 트렌드 점수

초기 30일은 다음 고정 가중치를 사용합니다.

- 파급력 35% (커뮤니티 수와 커뮤니티군 다양성)
- 조회 성과 25% (시간당 조회수 65%, 조회수 백분위 35%)
- 댓글 및 반응률 15%
- 채널 내부 순위 10%
- 검색 수요 10% (미수집 시 나머지 항목으로 재정규화)
- 최신성 5%

조회수는 작성 시각부터 수집 시각까지의 평균 시간당 조회수와 당일 조회수 백분위로 보정합니다. 내부 스냅샷이 쌓인 뒤에는 11시·15시·19시 사이의 실제 조회 증가량으로 교체합니다. 채널 내부 순위는 `rank`와 `candidateCount`로 0~100점화합니다. 30일 이후에는 `futureCommunityCount24h`와 `survivedNextDay`를 목표값으로 Ridge 회귀계수를 매월 다시 계산하도록 설계합니다.

점수 구간은 다음과 같습니다.

- 80점 이상: 이번 주 반드시 제작
- 65~79점: 제작 우선 후보
- 50~64점: 추가 관찰
- 50점 미만: 제외

영상 후보는 60점 이상이면서 파급력 60점 이상, 합산 조회수 10만 회 이상, 또는 6시간 내 조회수 5만 회 이상 중 하나를 만족해야 합니다. 따라서 교차 확산 전이라도 압도적인 고조회 주제는 검토할 수 있고, 저조회 단일 커뮤니티 글은 영상 후보에서 제외됩니다.

## 자동 토픽 통합

제목의 순번, 확장자, 특수문자, 반복 자모와 `근황`, `실시간`, `충격` 같은 불용어를 제거합니다. 이후 토큰 Jaccard와 공통 토큰 비율을 이용해 유사 제목을 하나의 주제로 묶습니다. 향후 의미 기반 분류가 필요해지면 KeyBERT·BERTopic·Kiwi를 선택적으로 연결할 수 있습니다.

## 커뮤니티군 보정

교차 확산 점수는 단순 커뮤니티 수 60%와 서로 다른 커뮤니티군 수 40%로 계산합니다. 비슷한 이용자층 내부에서만 재게시된 주제가 대중 트렌드로 과대평가되는 것을 줄입니다.

## 30일 이후 재학습

`model/training.example.json` 형식으로 일별 특징값과 24시간 결과를 저장합니다. 30일 이상 누적되면 다음 명령으로 상관계수와 Ridge 계수를 계산합니다.

```bash
npm run train -- model/training.json
```

학습 결과는 `model/weights.json`에 저장되며 이후 보고서 생성 시 자동으로 사용됩니다. 표본이 30일 미만이면 학습을 중단하고 초기 고정 가중치를 유지합니다.

## 외부 검증 원칙

Google Trends, 네이버 데이터랩, 본문 추출은 유용하지만 비공식 API의 호출 제한과 사이트 정책 영향을 받습니다. 연결되기 전에는 커뮤니티 점수에 임의로 섞지 않으며, 연결 후에도 별도의 검색 수요 보조지표로 검증한 뒤 회귀 학습을 통해 유효성이 확인된 경우에만 가중치에 포함합니다. 검토한 저장소는 [`REFERENCES.md`](REFERENCES.md)에 정리했습니다.

## 확장·검증 파이프라인

후보 주제는 `커뮤니티 발견 → 연관어 확장 → 검색 상승 검증 → 유튜브 경쟁 검증 → 제작 결정` 순서로 처리합니다. 설정은 [`config/integrations.json`](config/integrations.json)에 있습니다.

- 연관어: 커뮤니티 제목의 n-gram과 공동출현어를 기본으로 만들고 네이버·YouTube 검색 결과 제목으로 보강
- 국내 수요: 네이버 데이터랩의 6시간·24시간·7일 변화율
- 글로벌 수요: 접근 권한이 있을 때 Google Trends 공식 API 사용
- 뉴스 확산: 네이버 검색 API의 뉴스·블로그 결과량과 최신 문서 증가
- 영상 기회: YouTube 검색 결과의 최근 영상 수, 조회수 중앙값, 상위 채널 집중도를 조합

외부 신호는 초기 커뮤니티 점수에 바로 더하지 않고 제작 여부를 결정하는 관문으로 사용합니다. 값이 없으면 0점이 아니라 `미수집`으로 표시합니다. 일일 JSON의 선택적 `research` 필드에 결과를 넣으면 HTML과 Markdown 리포트에 자동 표시됩니다.
